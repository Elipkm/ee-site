AI tools produce code quickly, but developers still need to understand the problem, communicate intent and judge the result.

**Part 1 – Think before you code:** pen and paper, clarifying requirements, expressing intent through names, interfaces and documentation, choosing the scope of a change and reviewing it critically.

**Part 2 – Demo:** a Spring Boot application built with Codex: how I describe a change, review the output and correct it. Plus a simple Markdown structure for giving the AI guidelines, rules and feature plans.

**Core message:** don't follow blindly. Build your own AI work process. Leverage its strengths.
